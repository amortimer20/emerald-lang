Emerald · v0

A tour of Emerald

Emerald is meant to be a good first language and a good working one — the same language, not a teaching version of a real one. This walks through it a feature at a time, with a small program for each.

Everything here was run. Every program on this page was executed by the compiler, and every output shown is what it actually printed — including all the mistakes near the end.

    The basics

    01 Hello

    A program is a list of things to do. There is no setup, no main function to write, and nothing to import — every .em file in the folder is part of the same program.

    # A program is just statements, run from the top down.

print("Hello, Emerald.")

# This is a comment.
#[ and this one
   spans lines ]#
    prints
    Hello, Emerald.

    02 Variables

    A var can change later. A const cannot — if you try, the program will not run, which is usually what you wanted.

    You can write down what kind of thing a variable holds, or leave it out and let Emerald work it out from the value. Both are equally checked; the type is there either way.

    var name = "Ada"        # a var can change
const YEAR = 1843       # a const cannot

var score: Int = 0      # you can write the type
var ratio = 0.5         # or let Emerald work it out

score = score + 10
score += 5

print("#{name}, #{YEAR}, #{score}, #{ratio}")
    prints
    Ada, 1843, 15, 0.5

    03 Numbers, text, and yes-or-no

    Four kinds of value to start with: Int for whole numbers, Float for numbers with a decimal point, String for text, and Bool for true or false.

    Everything is an object, so you ask a number a question the same way you ask anything else — with a dot. There are no separate global functions to remember.

    var whole = 7           # Int
var exact = 7.5         # Float
var word = "seven"      # String
var yes = true          # Bool

print(7 + 2)
print(7 - 2)
print(7 * 2)
print(7 / 2)            # gives a Float
print(7 // 2)           # whole-number division
print(7 % 2)            # remainder
print(7 ** 2)           # power

print(word.count())
print(word.upper())
print(word.reverse())
print(whole.even?())
print(yes and not false)

    A method whose name ends in ? always answers true or false. You can tell what even? gives back without looking it up, and Emerald checks that the promise is kept.

    04 Putting values into text

    Write #{ } inside a string and whatever is in the braces gets worked out and dropped in. Anything can go in there, not just a name.

    var name = "Grace"
var ships = 3

print("#{name} has #{ships} ships.")
print("Next year: #{ships + 1}")
print("Shouted: #{name.upper()}")
    prints
    Grace has 3 ships.
Next year: 4
Shouted: GRACE

    05 Choosing

    if works how you would expect. unless is the opposite, for when writing if not would be harder to read than the thing it means.

    An if can also produce a value rather than doing something, and it can sit at the end of a line as a guard.

    var score = 82

if score >= 90 {
    print("A")
}
else if score >= 80 {
    print("B")
}
else {
    print("something else")
}

unless score > 100 {
    print("that is a believable score")
}

# if can produce a value
var grade = if score >= 80 then "pass" else "resit"
print(grade)

# and it can guard a single line
print("nearly an A") if score > 80
    prints
    B
that is a believable score
pass
nearly an A

    06 Repeating

    for walks a range, a list, a set, or a string — and a dictionary in pairs, for (key, value) in scores. There is no three-part C-style loop, so there is nothing else for it to be confused with.

    while is the other loop, and it takes the condition the plain way round. break leaves a loop and continue skips to the next turn, and both take the one-line guard.

    for i in 1..3 {
    print("count #{i}")
}

for animal in ["cat", "dog"] {
    print(animal)
}

for letter in "hi" {
    print(letter)
}

var left = 3
while not left.zero?() {
    print("t-minus #{left}")
    left -= 1
}

3.times { print("again") }

for n in 1..10 {
    continue if n % 3 != 0
    break if n > 6
    print("multiple of three: #{n}")
}

    07 Lists

    A list holds many of one kind of thing, in order. It grows and shrinks as you go, and it knows what it contains — a list of numbers will not let a word in.

    var numbers = [5, 3, 8, 1]

print(numbers.count())
print(numbers[0])
print(numbers.sum())
print(numbers.sort().join(", "))

numbers.add(10)
print(numbers.join(" "))

numbers[0] = 99
print(numbers[0])

var names: List<String> = ["ada", "alan"]
print(names.join(" and "))
    prints
    4

    When you do write the type down, it is List<String> — a list, and then what is in it.

    08 Dictionaries

    A dictionary maps keys to values — a name to an age, a word to how often it appeared. Looking one up gives back "the value, or nothing", because a key that is not there is an ordinary thing to happen rather than a mistake.

    That is why .or(0) appears below: it says what a miss should count as. Counting things is what dictionaries are mostly for, and it comes out as one line.

    var ages = ["ada": 36, "bo": 7]

print(ages["ada"].or(0))
print(ages["nobody"].or(0))
print(ages.count())

ages["cy"] = 12
ages["bo"] += 1

print(ages.keys().join(", "))
print(ages.has_key?("cy"))

var counts: Dictionary<String, Int> = [:]
for word in "the cat the mat".split(" ") {
    counts[word] = counts[word].or(0) + 1
}
print(counts["the"].or(0))
    prints
    36
0
2

true
2

    Keys are not only text and numbers. A struct works too: it cannot be changed once built and it compares by its fields, so two made the same way are one key — which is what lets a position, a date or a pair of coordinates be the thing you look something up by.

    struct Point {
    var x: Int
    var y: Int
}

var label: Dictionary<Point, String> = [:]
label[Point(1, 2)] = "start"
label[Point(4, 0)] = "corner"

print(label[Point(1, 2)].or("?"))
print(label.count())

var seen = [Point(1, 2), Point(1, 2)].to_set()
print(seen.count())
    prints
    start
2
1

    An object works as a key as well, but it is held by which object it is rather than by what it contains — two dogs both named "rex" are two keys. A struct is the one to reach for when you want look-alikes to count as one.

    Things stay in the order you put them in. A program whose output shuffles between runs is miserable to debug, because you cannot tell it from a mistake of your own.

    09 Sets

    A set remembers whether something is in it, not how many times or in what position. Duplicates collapse on the way in. Write one as a list and convert.

    var vowels = ["a", "e", "i", "o", "u"].to_set()

print(vowels.count())
print(vowels.contains?("e"))

var rolls = [3, 1, 3, 2, 1].to_set()
print(rolls.to_list().join(", "))

var monday = ["ada", "bo"].to_set()
var tuesday = ["bo", "cy"].to_set()
print(monday.union(tuesday).to_list().join(", "))
print(monday.intersect(tuesday).to_list().join(", "))

    Functions and blocks

    10 Functions

    A function says what it takes and what it gives back. A parameter can have a default, so the common call stays short. Two functions can share a name as long as a call could always tell them apart.

    func double(n: Int): Int {
    return n * 2
}

func greet(name: String, greeting: String = "Hello"): String {
    return "#{greeting}, #{name}!"
}

# A function that answers yes or no ends in ?
func old_enough?(age: Int): Bool {
    return age >= 18
}

# Two functions can share a name if a call can tell them apart
func area(side: Int): Int { return side * side }
func area(width: Int, height: Int): Int { return width * height }

print(double(21))
print(greet("Ana"))
print(greet("Bo", "Welcome"))
print(old_enough?(20))
print(area(4))
print(area(4, 5))
    prints
    42
Hello, Ana!
Welcome, Bo!
true

    11 Blocks

    A block is a piece of code you hand to something else to run. map makes a new list by running your block on each item, filter keeps the ones your block says yes to, and each just runs it.

    You never have to say what n is below. The list is a list of Int, so n is an Int, and n.even?() is checked like anything else.

    var numbers = [5, 3, 8, 1, 9]

print(numbers.map { n => n * 2 }.join(", "))
print(numbers.filter { n => n.even?() }.join(", "))
print(numbers.any? { n => n > 8 })

# find might not find anything, so it hands back "an Int or nothing"
print(numbers.find { n => n > 100 }.or(0))

var total = 0
numbers.each { n => total += n }
print(total)
    prints
    10, 6, 16, 2, 18
8
true
0
26

    12 Functions are values

    Everything in the last section was a built-in taking a block. Your own functions can take one too, and the type you write for it is just the function's header with the name taken off.

    func greet(name: String): String { return "hi #{name}" }
#                    the function above has the type below
#        func(String): String

    So a function that wants a block says what shape of block it wants. If there is nothing to hand in and nothing to give back, that is just func().

    func do_twice(action: func()) {
    action()
    action()
}

do_twice { print("hi") }
    prints
    hi
hi

    You do not have to say what n is here either. transform said its block takes an Int, so n is an Int — the same help the built-in list methods give, now on a function you wrote yourself.

    func transform(items: List<Int>, change: func(Int): Int): List<Int> {
    return items.map { n => change(n) }
}

print(transform([1, 2, 3]) { n => n * 2 }.join(", "))

# a function you already have goes where a block does
func double(n: Int): Int { return n * 2 }

func apply(n: Int, change: func(Int): Int): Int { return change(n) }

print(apply(21, double))
    prints
    2, 4, 6
42

    And because a function is a value, it goes in a variable, in a list, or in a field — which is how something remembers what to do later.

    class Button {
    var label: String
    var on_click: func()

    constructor(label: String, on_click: func()) {
        self.label = label
        self.on_click = on_click
    }

    func press() {
        print("pressing #{self.label}")
        self.on_click()
    }
}

Button("OK") { print("clicked") }.press()
    prints
    pressing OK
clicked

    button.on_click is the function itself; button.on_click() runs it. The brackets are what tell them apart.

    That rule is not only for fields. A method named without its brackets is the method itself, with the object it belongs to already attached — so you can hand one over the same way, and it remembers which object it came from.

    class Dog {
    var name: String

    constructor(name: String) { self.name = name }

    func speak(): String { return "#{self.name} says woof" }
}

func announce(what: func(): String) { print(what()) }

var rex = Dog("Rex")
var fido = Dog("Fido")

# no brackets: the method itself, not what it answers
announce(rex.speak)
announce(fido.speak)

# with brackets: the answer
print(rex.speak())
    prints
    Rex says woof
Fido says woof
Rex says woof

    The methods that came with the language work the same way. There is no separate rule for them, which is the point — you should not have to know whether something was written by you or shipped with Emerald in order to know how to write it down.

    func shout(f: func(): String): String { return f() }

var word = "seven"
print(shout(word.upper))
print(shout(word.reverse))
    prints
    SEVEN
neves

    The one exception is a method that takes a block, like map. What map gives back is whatever your block gives back, so until there is a block there is nothing to say about it — and Emerald says exactly that rather than guessing.

    This is the reason brackets are required on every call, even one with nothing to pass. If rex.speak ran the method, there would be no way left to write down the method itself — and connecting something up later, like a button to the thing it should do, is a large part of what you use a class for.

    Forgetting them is the mistake the rule creates, so the compiler is direct about it.

    class Cat {
    func speak(): String { return "meow" }
}

print(Cat().speak)
    emerald run
    main.em:5  This shows Cat().speak itself, not what it answers.

    5 | print(Cat().speak)

  It is func(): String. Add parentheses to call it:  Cat().speak()

    Values that might not be there

    13 Values that might not be there

    A String always holds a string. Sometimes you need "or nothing at all" — so you add a ?.

    Emerald will not let you use a String? until you have checked it. That is the whole point: the crash where something turned out to be empty cannot happen, because the program will not run until you have said what to do about it.

    var certain: String = "Ada"     # always a String
var unsure: String? = nothing   # a String, or nothing at all

# Emerald will not let you read unsure until you have checked it
if unsure != nothing {
    print(unsure.count())
}
else {
    print("there was nothing there")
}

# .or supplies a fallback
print(unsure.or("nobody"))

# .must says "I know this is there" — and stops the program if it is not
var found: Int? = "42".to_int_maybe()
print(found.must())
    prints
    there was nothing there
nobody
42

    After if unsure != nothing, unsure is an ordinary String for the rest of that block — you do not unwrap it or write anything extra. The check is the unwrapping.

    14 Reaching through a chain

    Checking works on a name, not on a path, so when several steps in a row might be missing you use ?. instead. It reads through the ? and stops at the first step that is not there.

    class City {
    var name: String
    constructor(name: String) { self.name = name }
}

class Trip {
    var destination: City?
    constructor(destination: City?) { self.destination = destination }
}

var booked = Trip(City("Leeds"))
var unbooked = Trip(nothing)

# ?. reads through the ?, and stops at the first step that is missing
print(booked.destination?.name.or("nowhere yet"))
print(unbooked.destination?.name.or("nowhere yet"))
    prints
    Leeds
nowhere yet

    Making your own types

    15 Classes

    A class describes a kind of thing: what it knows, and what it can do. The constructor is what runs when you make one. Inside, self means "this one".

    class Dog {
    var name: String
    var legs: Int = 4

    constructor(name: String) {
        self.name = name
    }

    func speak(): String {
        return "Woof"
    }

    func introduce(): String {
        return "#{self.name} says #{self.speak()}"
    }
}

var rex = Dog("Rex")
print(rex.introduce())
print(rex.legs)

rex.name = "Rexington"
print(rex.name)
    prints
    Rex says Woof
4
Rexington

    Every field has to have a value by the time the constructor finishes. Forget one and the program will not run — which is the mistake this catches most often in practice.

    Printing rex itself would show <Dog>, which tells you nothing. Give the class a to_string and it says what you wrote instead — everywhere a value turns into text, without you asking.

    class Cat {
    var name: String
    constructor(name: String) { self.name = name }

    func to_string(): String {
        return "#{self.name} the cat"
    }
}

var kit = Cat("Kit")
print(kit)
print("I met #{kit}")
print([kit, Cat("Moss")])
    prints
    Kit the cat
I met Kit the cat
[Kit the cat, Moss the cat]

    It has to be written func to_string(): String with nothing in the brackets. It is the one method the language calls on your behalf, so it is the one whose shape is fixed.

    16 A class without the braces

    Most of the time a file holds one class, and then the braces around it are wrapping the entire file and indenting every line inside it for no gain. So you can leave them off: name the class on the first line, and everything below is its body, all the way to the end of the file.

    It is the same declaration — extends and with work exactly as they do above — with the body implied instead of written out.

    # rect.em — one class, so no braces and no extra indenting
class Rect

var width: Int
var height: Int

constructor(width: Int, height: Int) {
    self.width = width
    self.height = height
}

func area(): Int { return self.width * self.height }

func square?(): Bool { return self.width == self.height }
    # main.em — every .em file in the folder is part of the same program,
# so there is nothing to import
var r = Rect(3, 4)
print(r.area())
print(r.square?())
print(Rect(5, 5).square?())
    prints
    12
false
true

    A file has one shape or the other: either one class written this way, or braces throughout. Because the body runs to the end of the file with nothing that stops it, a second class written underneath is a class inside the first — which is occasionally what you want for a small helper, and otherwise a sign the second one belongs in its own file.

    Godot names the type after the file instead. Emerald does not, so that class Rect is a thing you can search for, and renaming a file cannot quietly rename a type.

    17 Properties, shared values, and private names

    A property looks like a field from the outside but runs code when you read it. static means the value or function belongs to the class itself rather than to any one of them.

    A name beginning with _ can only be used inside the class and anything that extends it. There is no keyword to learn, and you can see that it is private at the place it is used rather than having to go and look at where it was declared.

    class Circle {
    static const PI = 3.14159
    static var made: Int = 0

    var radius: Float

    # A property looks like a field from the outside, but runs code.
    var area: Float {
        get { return Circle.PI * self._squared() }
    }

    constructor(radius: Float) {
        self.radius = radius
        Circle.made += 1
    }

    # A name starting with _ belongs to the class. Code outside cannot call it.
    func _squared(): Float { return self.radius * self.radius }

    static func unit(): Circle { return Circle(1.0) }
}

var c = Circle(2.0)
print(c.area)
print(Circle.unit().area)
print(Circle.made)
    prints
    12.56636
3.14159
2

    18 Building on another class

    extends means "everything that one has, plus this". To replace a method the other class already has, say override — you are taking something over, so you say so.

    class Animal {
    var name: String

    constructor(name: String) { self.name = name }

    func speak(): String { return "..." }

    func introduce(): String { return "#{self.name} says #{self.speak()}" }
}

class Dog extends Animal {
    override func speak(): String { return "Woof" }
}

class Cat extends Animal {
    override func speak(): String { return "Meow" }
}

var pets = [Dog("Rex"), Cat("Momo")]
for pet in pets {
    print(pet.introduce())
}
    prints
    Rex says Woof
Momo says Meow

    introduce was written once, in Animal, and it calls self.speak() — which finds whichever version belongs to the actual animal. A class can only extend one other class.

    The word is not decoration. Leave it off and Emerald stops you, because replacing a method by accident is a real and nasty mistake — you can break a class you never opened, just by picking a common name for your own method.

    class Timer {
    var ticks: Int = 0

    func reset() { self.ticks = 0 }

    func run() {
        self.ticks = 5
        self.reset()
    }
}

class RaceTimer extends Timer {
    var laps: Int = 0

    func reset() { self.laps = 0 }        # written without knowing Timer has one
}
    emerald run
    main.em:15  reset replaces Timer.reset, so it says override.

   15 |     func reset() { self.laps = 0 }        # written without knowing Timer has one

  Write:  override func reset(...)
  If you did not mean to replace it, Timer already has a reset taking the same things, and calling it will now reach this one instead. Rename yours, or give it different parameters so the two are overloads.

    When the new class has something of its own to set up, it writes its own constructor and starts it by calling the one above with super. That is how the base gets to fill in its own part — you say what to pass it, and it does the rest.

    class Vehicle {
    var wheels: Int
    var name: String

    constructor(name: String, wheels: Int) {
        self.name = name
        self.wheels = wheels
    }

    func describe(): String { return "#{self.name}, #{self.wheels} wheels" }
}

class Bike extends Vehicle {
    var gears: Int

    constructor(name: String, gears: Int) {
        super(name, 2)          # build the Vehicle part first
        self.gears = gears
    }

    override func describe(): String {
        return "#{super.describe()}, #{self.gears} gears"
    }
}

print(Bike("commuter", 8).describe())
    prints
    commuter, 2 wheels, 8 gears

    super means one thing — the class above — and you can do two things with it. super(...) runs its constructor; super.describe() calls a method it wrote.

    super(...) has to be the first line. Until it has run, the fields the base looks after are still empty, so nothing else can safely go before it. And you only need to write it when the base's constructor wants something — if it takes nothing, it is called for you.

    What you must not do is fill in the base's fields yourself. Emerald will not let you, and the reason is worth seeing: Vehicle might do something with the values on the way in, and a class that sets the fields directly quietly skips all of it.

    class Vehicle {
    var wheels: Int
    var name: String

    constructor(name: String, wheels: Int) {
        self.name = name
        self.wheels = wheels
    }
}

class Bike extends Vehicle {
    var gears: Int

    constructor(name: String, gears: Int) {
        self.gears = gears
    }
}
    emerald run
    main.em:14  Vehicle's constructor needs 2 arguments, so Bike has to say what to pass it.

   14 |     constructor(name: String, gears: Int) {

  Call it first:  super(...)
  Vehicle's constructor takes (String, Int).

    And when you do replace a method, super is the one you replaced — useful when you want to add to it rather than throw it away.

    class Greeter {
    func greet(): String { return "hello" }
}

class LoudGreeter extends Greeter {
    override func greet(): String { return "#{super.greet()}!!!" }
}

print(LoudGreeter().greet())
    prints
    hello!!!

    19 Traits

    A trait says what a type must have, and can hand it things in return. Unlike extends, a class can mix in as many traits as it likes.

    Below, Swimmer demands a stamina and gives back a swim. Neither class writes swim; both get it.

    # A trait says what a type must have, and can hand it things in return.
trait Swimmer {
    abstract func stamina(): Int        # you must write this

    func swim(): String {               # you get this for free
        return "swimming for #{self.stamina()} minutes"
    }
}

class Dog with Swimmer {
    func stamina(): Int { return 30 }
}

class Duck with Swimmer {
    func stamina(): Int { return 90 }
}

print(Dog().swim())
print(Duck().swim())
    prints
    swimming for 30 minutes
swimming for 90 minutes

    A trait can also leave a type open rather than a method — Iterable below asks for each, names what each hands out as Item, and gives back map, filter, count and more, all written just once. Deck only ever writes each; everything else arrives with it.

    class Card {
    var name: String
    var value: Int
    constructor(name: String, value: Int) {
        self.name = name
        self.value = value
    }
}

class Deck with Iterable {
    type Item = Card
    var cards: List<Card>
    constructor(cards: List<Card>) { self.cards = cards }

    func each(step: func(Card)) {
        for c in self.cards { step(c) }
    }
}

var deck = Deck([Card("Ace", 1), Card("King", 13), Card("Queen", 12)])

print(deck.map { c => c.name }.join(", "))
print(deck.filter { c => c.value > 10 }.count())
    prints
    Ace, King, Queen
2

    map's own answer type is never written down anywhere — c => c.name is what tells it, the same way a block's own parameter is inferred everywhere else in this tour.

    20 Operators on your own types

    There is no special syntax for making + work on something you wrote. a + b is a.add(b), so you write an ordinary method and mix in the trait that names it.

    One compare answers all four of <, >, <= and >=. And += goes through the same add you already wrote.

    The to_string from §15 is doing its job here too: print(lunch + coffee) needs nothing after it.

    struct Money with Addable, Equatable, Ordered {
    var cents: Int

    func add(other: Money): Money { return Money(self.cents + other.cents) }
    func equals?(other: Money): Bool { return self.cents == other.cents }
    func compare(other: Money): Int { return self.cents - other.cents }

    func to_string(): String {
        var pennies = self.cents % 100
        return "$#{self.cents // 100}.#{if pennies < 10 then "0#{pennies}" else "#{pennies}"}"
    }
}

var lunch = Money(1250)
var coffee = Money(450)

print(lunch + coffee)
print(lunch > coffee)
print(lunch == Money(1250))

var total = Money(0)
total += lunch
print(total)
    prints
    $17.00
true
true
$12.50

    21 Square brackets on your own types

    Same idea. Indexable gives you board[0] for reading if you write at, and writing as well if you also write set_at. Leave set_at out and the type is read-only.

    class Board with Indexable {
    var squares: List<String>

    constructor(size: Int) {
        self.squares = []
        size.times { self.squares.add(".") }
    }

    func at(square: Int): String { return self.squares[square] }
    func set_at(square: Int, mark: String) { self.squares[square] = mark }
}

var board = Board(3)
board[0] = "X"

    22 Structs

    A struct is a small value that never changes once it is made — a point, an amount of money, a color. Because it cannot change, you do not have to write a constructor: Emerald builds one from the fields, in the order you declared them.

    You "change" a struct by making a new one, which is why moved_by returns a Point rather than editing this one.

    # A struct is a small value that never changes once it is made.
struct Point {
    var x: Int
    var y: Int

    # No constructor written — Emerald builds one from the fields, in order.

    func moved_by(dx: Int, dy: Int): Point {
        return Point(self.x + dx, self.y + dy)
    }
}

var here = Point(2, 3)
var there = here.moved_by(1, 1)

print("#{here.x}, #{here.y}")
print("#{there.x}, #{there.y}")
    prints
    2, 3
3, 4

    And because a struct is its contents, two structs holding the same things are the same thing. You do not have to write that; it is what being a value means.

    print(Point(2, 3) == Point(2, 3))
print(Point(2, 3) == Point(9, 9))

var route = [Point(0, 0), Point(2, 3)]
print(route.contains?(Point(2, 3)))
    prints
    true
false
true

    A class is different: two classes are the same only if they are the same one. That is the honest answer when nothing has said otherwise — and a class can say otherwise, which is the next section but one.

    23 Enums

    An enum is a closed set of names. The alternative is passing strings around, and then red?("HAERTS") compiles happily and quietly does the wrong thing. Suit.HAERTS cannot be spelled at all.

    enum Suit { HEARTS, DIAMONDS, CLUBS, SPADES }

var card = Suit.HEARTS

print(card)
print(card.name)
print(card == Suit.HEARTS)

for suit in Suit.values {
    print(suit.name)
}

# A function taking a Suit cannot be handed anything else —
# a misspelled string would have compiled and then misbehaved.
func red?(s: Suit): Bool {
    return s == Suit.HEARTS or s == Suit.DIAMONDS
}

print(red?(Suit.CLUBS))
    prints
    Suit.HEARTS
HEARTS
true
HEARTS
DIAMONDS
CLUBS
SPADES
false

    Things going wrong

    24 When something goes wrong on purpose

    When a function cannot do what it was asked, it can throw. Whoever called it can catch that and decide what to do. Notice throw ... if ... using the same one-line guard as everything else.

    The guard also does the work of a check. A throw leaves the function, so everything below it is the case where the check held — age is an Int from there on, and needs no .must() to say so.

    func age_from(text: String): Int {
    var age = text.to_int_maybe()
    throw "\"#{text}\" is not a number" if age == nothing
    return age
}

for input in ["42", "banana"] {
    try {
        print("age: #{age_from(input)}")
    }
    catch e {
        print("could not read that: #{e.message}")
    }
}
    prints
    age: 42
could not read that: "banana" is not a number

    A program can say what kind of thing went wrong. Error is an ordinary class, so you declare your own by extending it — and then a catch can name the one it handles.

    The clauses are tried in the order you write them, so put the specific one first. The last catch here has no type, which means it takes anything the ones above it did not.

    class TooOld extends Error { }

func age_in_range(text: String): Int {
    var age = text.to_int_maybe()
    throw "that is not a number" if age == nothing
    throw TooOld("#{age} is not a believable age") unless age.between?(0, 130)
    return age
}

for input in ["42", "900", "banana"] {
    try {
        print("age: #{age_in_range(input)}")
    }
    catch e: TooOld {
        print("out of range: #{e.message}")
    }
    catch e {
        print("could not read that: #{e.message}")
    }
}
    prints
    age: 42
out of range: 900 is not a believable age
could not read that: that is not a number

    25 Tests

    A test is a function marked @test, in a file whose name ends in _test.em. assert states something you believe is true.

    When an assertion fails it shows you the line you wrote and both sides of it, so you do not have to go back and add prints to find out what the values actually were.

    # main.em
func double(n: Int): Int { return n * 2 }

print(double(21))

    assert double(4) == 8
    assert double(0) == 0
    return true
}

@test

    return true

    When a message mentions emerald explain, that is an offer. Run it and you get the same mistake shown as a small worked example — the broken version, the fixed version, and why.

    explain
    Reaching through a value that might be nothing

  This does not work:

      var name: String? = nothing
      print(name.count())

  This does:

      var name: String? = nothing
      if name != nothing {
          print(name.count())
      }

  A String? holds either a String or nothing, and nothing cannot be counted.
  Checking it first is what tells the compiler which one it has — after that
  check, name is an ordinary String for the rest of the block.

  When any answer will do, ask for one:  name.or("unknown").count()

  The check works on a name, not on a path, so a chain gets ?. instead. It
  reads through the ? and puts it back on the answer, stopping at the first
  step that is missing:

      print(user.address?.city?.name.or("unknown"))

    Working with it

    27 The tools

    One command, a handful of things it does. There is no project file to configure and no build to set up — emerald new makes a folder with one file in it, and every .em file you add beside it joins the same program.

    emerald
    emerald — v0 prototype

  emerald new <name>        start a project
  emerald run <file.em>     run a program
  emerald check <file.em>   look for problems without running
  emerald repl              try code a line at a time
  emerald test [path]       run every @test function
  emerald fmt [path]        format code, one way, no settings
  emerald explain           explain the last error
  emerald <file.em>         same as run

  build, ship, add          named, and not buildable yet — try one to see why

Every .em file beside the entry file is part of the project — no imports needed.
